# 安全模型

## 受保护资产

- 授权工作区之外的源码和数据。
- 任务未授权修改的现有工作区文件。
- API 凭证和模型提供商密钥。
- 项目测试与验证证据的完整性。
- 运行产物中保存的机密源码或提示内容。

## 信任边界

用户任务、目标仓库、模型输出、生成代码和 Shell 输出都可能不可信。因此，授权与证据决策应由确定性运行时防护负责，而不是委托给模型文本。

## 当前控制

- 路径归一化和工作区边界检查。
- 在仓库发现、文本搜索、接口检查、验证发现和工作区基线中验证符号链接目标。
- 只读策略和语义写入范围策略。
- 只读分析期间禁用项目执行，并提供独立的显式仅验证路径，该路径不会启用写工具。
- 工作区基线和动作后变更审计。
- Shell 执行前的命令策略检查。
- 拒绝通过 `find`、原地 `sed` 和 Git 输出选项进行间接写入或执行。
- 在不开放内联 Shell、重定向或解释器选项的情况下，支持直接 Shell 脚本和标准输入验证。
- 结构化工具参数与结果。
- 隔离 Agent 生成的验证测试。
- 限制轮次、修复调用、重复动作和重复失败。
- 最终门禁拒绝失败或缺失的必需证据。
- 使用 Git 忽略本地凭证和运行产物。
- 对导出的审计包执行纵深文本脱敏并生成清单。

## 范围之外

项目当前不提供：

- 内核、容器或虚拟机级隔离；
- 对恶意依赖安装或测试代码的完整防护；
- 命令过滤能够阻止所有 Shell 逃逸的形式化证明；
- 自动脱敏审计中的所有密钥或私有源码片段；
- 安全多租户执行。

## 推荐部署方式

对每个不可信任务使用临时容器或虚拟机，并配置非特权用户、挂载工作区、受限网络、资源限制和短期模型凭证。在 Agent 输出与部署之间保留人工审查。
