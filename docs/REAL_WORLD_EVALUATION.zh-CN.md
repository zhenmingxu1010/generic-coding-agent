# 真实仓库修复评测

可复现试点使用来自公开 Git 仓库和 BugsInPy 元数据的 4 个历史 Python 缺陷。每个案例都固定缺陷提交和历史修复提交。

## 评测协议

Agent 获得缺陷提交的干净检出和简短 Issue 风格任务，看不到历史补丁、修复后源码或隐藏测试。

评测器独立要求：

- 隐藏回归在缺陷提交上失败；
- 同一回归在历史修复提交上通过；
- Agent 运行后受保护测试源码保持不变；
- 隐藏验收只在 Agent 停止后通过。

`tqdm-tenumerate-start` 案例还注入了由评测器拥有的 NumPy 特殊分支兼容性测试。它捕获了一个通过历史回归但改变无关返回形态的过度修复。通用最小差异策略加强后，Agent 生成了与历史修复相同的一行实现变更。

## 当前试点结果

| 案例 | 外部结果 | Agent 最终门禁 | 变更项目文件 | Token | 受保护测试变更 |
|---|---:|---:|---:|---:|---:|
| PySnooper 文件输出 | 已解决 | `verified_ok` | 1 | 64,074 | 0 |
| tqdm `tenumerate(start)` | 已解决 | `verified_ok` | 1 | 77,711 | 0 |
| tqdm 未知总量与 scale | 已解决 | `verified_ok` | 1 | 69,837 | 0 |
| Cookiecutter 失败钩子清理 | 已解决 | 保守假阴性 | 3 | 219,429 | 0 |

脱敏后的机器可读结果位于 [`evaluations/real_world/pilot-summary.json`](../evaluations/real_world/pilot-summary.json)。原始报告包含机器专用工作区路径和模型审计位置，因此只保留在本地。

v2 摘要把 Agent 运行后的隐藏结果视为评测器真值，并与 Agent 最终声明比较。在这个小型试点中：

- 外部验收：4/4；
- 真阳性成功声明：3；
- 假阳性声明：0；
- 假阴性声明：1；
- 成功声明精确率：100%；
- 成功声明召回率：75%；
- 受保护修改案例：0；
- 模型调用：47；
- 报告 Token：431,051；
- 多文件变更案例：1。

样本很小，因此精确率和召回率仅具有描述意义。多文件案例只证明一个被接受的三文件修复，而不是广泛的仓库级能力。该案例的假阴性也记录了当前限制：实现正确，但自主验证没有产生足够可信的直接证据。

## 试点发现的通用改进

- Agent 与目标项目可以使用不同的 Python 解释器。
- 保留虚拟环境启动器符号链接，而不是解析到会丢失已安装包的基础解释器。
- 隔离行为探针可以导入项目代码，而不复制或修改真实工作区输入。
- 静态接口检查可以识别导入和重新导出的 Python 符号。
- 修改源码前记录现有失败测试；只有最终收集的测试数不少于基线，且所有剩余失败具有相同测试、异常类型和归一化消息时，才会降级这些失败。
- 修复提示要求最小且有证据的行为差异，并把无关分支视为兼容性约束。
- 初始多文件变更可以在验证前完成有界实现批次，失败后的修复仍采用编辑后立即验证。
- 验证探针在执行前拒绝确定的本地调用参数数量错误；捕获/清理场景应注入底层失败，而不是依赖脆弱的全栈夹具。

## 限制

4 个缺陷是有用的冒烟测试，但不构成统计上有意义的基准。唯一的多文件案例只证明一种错误传播/清理修复，不代表复杂 Issue 解决广度。下一轮应增加更多多文件变更、含糊 Issue、依赖/API 迁移和更大测试套件仓库。当存储和可复现运行时条件具备时，应单独报告 SWE-bench 或同类容器化基准。

## 复现

命令和模式见 [`evaluations/real_world/README.md`](../evaluations/real_world/README.md)。运行器不会执行网络安装；调用方提供完整本地源码克隆和目标测试解释器，从而将依赖或解释器失败报告为环境失败，而不是 Agent 失败。
